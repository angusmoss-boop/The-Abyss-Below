# Wild Waters verification

The supported current runner is:

```sh
python tests/build_release.py
python tests/run_v0150.py --group all --jobs 2
```

Requirements: Python, Playwright for Python, a Chromium executable discoverable as `chromium`, and Node.js. Preview generation additionally uses Pillow. This package does not install those tools automatically.

The test harness loads the actual HTML, CSS and JavaScript from the project. It substitutes local storage and explicitly enables the gated test hooks. These hooks create synthetic saves/equipment/positions, not user data. Browser mechanics tests do not imply real web hosting, service-worker networking or physical-phone performance.

## Current suites

The runner has 17 suites:

- **wild-mechanics**: 25 seeded maps, hazard counts/clearances, stable resource/rock generation, swept mine collisions, shield overflow, predator drops, permanent clearing, sonar timing, darkness, fish designs/behaviour, vent phases/flow/damage, seabed retraction and remote-explosion safeguards.
- **wild-migration**: a stored snapshot originally generated by the archived v0.14.0 code, including finite pickups and bought upgrades/ammo; actual migration to current code, old-ship encounter protection, exact current-version wildlife/time restore.
- **audio-signal**: actual Chromium Web Audio signals compared with a quiet baseline, independent sliders, mute, pause, rate limits and voice cap. This is not a human listening test.
- **regression**, **systems**, **resume**, **survey**, **harbour**, **geometry**, **achievements**, **migration**, **ui**, **touch**, **explorer-ui**, **release**, **sync**, **worker**: retained gameplay/upgrade/campaign/menu coverage, prior migration fixture, current runtime/checksum wiring and mocked version/worker boundaries. All run against the current files.

`verification/v0.15.0/results-all.json` records suite outcomes, completion timestamps and production runtime hashes. Per-suite `.log` files contain assertions/results. Historical reports and earlier test versions are retained as development history, not evidence for this release.

To regenerate the previous-version migration fixture from the actual archive:

```sh
python tests/v0150_wild_migration_test.py /path/to/the-abyss-below-v0.14.0-complete.zip
```

Without the archive argument, the migration test uses `tests/fixtures/v0140_campaign_wild.json`, which was generated in that way. Other existing tests may use earlier retained synthetic migration fixtures.

## Previews

```sh
python tests/v0150_wild_previews.py
```

Generated scenery screenshots use synthetic equipment and positions. The four-species composition deliberately brings all species together through test-only fixtures, then runs the production renderer/schooling simulation. The animation is a series of real game frames. None is a user's save or generated concept art.

## Optional real offline integration

```sh
python tests/v0150_live_pwa_test.py
```

This performs actual local HTTP/service-worker/offline navigation rather than mocked network responses. In this environment it was blocked by `net::ERR_BLOCKED_BY_ADMINISTRATOR`; its failure is separately recorded in `verification/v0.15.0/live-pwa.json`. It is not counted among the 17 passing suites. Run on an unrestricted local browser and also test the actual deployed site before claiming offline readiness.

Still required before an Android release: physical-device touch/performance/heat/battery testing, listening and audio mix review, hosted update/offline checks, storage stress tests and a full balance playthrough. This build is not an AAB or Android package.
